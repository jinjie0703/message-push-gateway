# Project Deep Diver Skill

当用户希望复盘自己的简历项目、准备大厂一二面项目深挖，或不知道如何在面试中高光展示自己的项目难点时，执行以下工作流。

## 1. 项目核心解剖与亮眼提炼 (Workflow)

请按照以下四步深度解剖用户的项目：

### 🌟 亮点包装与技术壁垒提炼
- **脱水提炼**：把用户平铺直叙的功能描述，升级为具有工业级水准的**高含金量技术亮点**（使用 STAR 法则与量化指标描述）。
- **难点无中生有/深度挖掘**：如果用户觉得项目“太简单”，从**高并发、大数量、极端边界、性能瓶颈、内存优化、网络异常**等工程维度，为其构思和挖掘 1~2 个真实可信的架构难点。

### 🎯 面试官视角：5 连环压力深挖预测
预测面试官看到该项目时最想拷问的 5 个层次，并给出能体现技术深度的“高情商防御话术”：
1. **架构选型关**：为什么当时选这个架构/技术方案，而不是其他的？
2. **极端场景关**：如果当前的流量/数据量放大 10 倍甚至 100 倍，你的系统哪里会先挂掉？怎么改造？
3. **线上 Bug 关**：这个项目开发过程中遇到最难搞的一个 Bug 是什么？你是怎么定位和解决的？
4. **性能极限关**：你在项目中做了哪些关键优化？核心指标（如首屏时间、内存占用、QPS）提升了多少？
5. **自我批判关**：如果让你现在重新做这个项目，你会推翻哪里的设计？为什么？

### 🛠️ 解决方案降维/进阶对比
针对项目中最大的技术挑战，给出：
- **初级方案（刚好能用）**：存在什么隐患。
- **当前方案（进阶落地）**：你项目里用到的方案。
- **终极方案（大厂海量业务架构）**：如果有无限资源或超高并发，业界最顶尖的解决方案是什么。

## 2. 输出规范
- 语气专业、犀利，极具实战指导性。
- 关键的技术设计模式、优化手段和底层原理词汇**加粗**显示。
